# Lanes of the north-star programme (epic #80)

A lane is one issue of the programme, worked in its own worktree on a branch from `origin/beta`, landed by the captain through a PR into `beta` after a cold review. The briefs here record what each lane was asked; the lane's report is its reply. The shared rules, which every brief assumes:

1. **Where you work.** The worktree cca gives you, on branch `lane/<name>` from `origin/beta` (never `main`; `main` is the stable line for quick fixes). `CARGO_TARGET_DIR` as cca set it under `~/bsv/targets/`, never inside the checkout and never a literal `/tmp`; scratch under `$TMPDIR`. Never the repository's own checkout, never a secrets file, never `~/vault/`, never `~/bsv/bsv-low/`. Never `cargo install` into `~/.cargo/bin`: a tool goes under `~/bsv/targets/<tool>-tools` with `cargo install --root`, at the head of your `PATH`.
2. **The proof rule.** Every claim with its command and the last lines of its output in the report. A test you did not run is not a test. `[X]` run, `[D]` told. A planted violation or a planted regression is the proof that a check bites: plant it, run, show the failure, revert.
3. **No network except reads.** `cargo` fetching crates, `git fetch`, reading a page. No POST, no publish, no GitHub write, no explorer call from a test (tests use `MockWalletServices` and `mockito`). Nothing is signed, broadcast or paid.
4. **The references, at pins.** The stack's charters at `~/bsv/bsv-stack-lean/docs/charters/` (`wallet.md`, `storage.md`, `broadcaster.md`, `tracker.md`) and `lean/Wallet.lean`; the stack's lane rules `~/bsv/bsv-stack-lean/docs/lanes/l2-README.md`; the CLI's lane shape `git -C ~/bsv/bsv-wallet-cli show origin/beta:docs/lanes/README.md`. Read with `git show <ref>:<path>` where a ref is named, never a working tree another captain may be on.
5. **One concern per PR.** A refactor never carries a behaviour change; a behaviour change changes its fixture in its own commit. Small commits with messages that say what and why. No file you add passes 800 lines (data goes to files). Only the lane the brief names edits `Cargo.toml` or `Cargo.lock`. The gate before you say done: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --lib`, and every test you added; CI runs with `RUSTFLAGS=-Dwarnings`.
6. **Never push, never a PR, never a tag, never `git stash`.** Commit on your lane branch; the captain lands. Never touch `main`, `beta`, `release/*` or another lane's branch. A public API shape, the schema, a pin, a version, a tag: the owner's word; stop and say so, do the rest.
7. **Wording.** No em dash anywhere. Never "first", never "conformant" without a run. No hostname of a deployment, no token shape, no account id. A CHANGELOG entry under `## [Unreleased]` (add the heading above the newest release if absent) only when behaviour or the public surface changes.
8. **The report.** It opens with the line `REPORT: STATUS done|blocked|walled`, then the base commit, your tip commit, the files, the commands and their tails, what is `[D]`, what you did not run and why, and what the captain must do at landing (the PR into beta, a branch protection context to add, an issue to file for each finding).
9. **Bounds.** The brief's limit is the limit; past it, `STATUS blocked` with what remains and what is committed.
10. **Test isolation.** Every `cargo test` runs as `env HTTP_PROXY=http://127.0.0.1:9 HTTPS_PROXY=http://127.0.0.1:9 ALL_PROXY=http://127.0.0.1:9 NO_PROXY=127.0.0.1,localhost,::1 no_proxy=127.0.0.1,localhost,::1 cargo test ...`, so nothing reaches a provider while the fixtures' loopback mock servers stay reachable; without the two `NO_PROXY` variables every fixture against a local mock fails (111 failures in one lane on 2026-10-26). Unit-test and `bench-support` service transports also refuse non-loopback requests independently of post mode and environment (#182, rule 28); run integration isolation coverage with `--features sqlite,remote,bench-support`, as the required CI integration step does, since Cargo builds its library dependency without `cfg(test)`. Never set the proxy variables for `git` or `gh`. Run `cargo fetch` once without them before the prefixed `cargo test`: the prefix also proxies cargo's index fetch, and a fresh target dir fails with `failed to get anyhow` otherwise. Every lane and every review builds into its own `CARGO_TARGET_DIR=$HOME/bsv/targets/<lane>`; a `cargo test` that prints no `Compiling` line for the tree under test ran another worktree's binary and is not a run.
