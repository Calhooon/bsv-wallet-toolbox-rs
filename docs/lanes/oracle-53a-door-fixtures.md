The work: golden fixtures for the public storage behaviour hosts depend on, replayed by `cargo test --test fixtures`.
- The harness: a directory test target `tests/fixtures/main.rs` with `mod storage;` (a sibling lane adds `mod ladders;` and `tests/fixtures/ladders.rs`; leave the hook, do not write that file). `tests/fixtures/storage.rs` loads every `tests/fixtures/data/storage/*.json`, builds `StorageSqlx::in_memory()` with a migrated schema and a test user from `test_vectors/keys/`, seeds the recorded inputs (coins, baskets, labels, the mock services' answers), runs the recorded calls in order, then dumps the exact rows after (outputs, transactions, proven_txs, proven_tx_reqs, tx_labels, output_baskets, commissions, the sync's leads where the call touches them) and the results, normalized (ids to their order of creation, txids and reference strings to `<txid:1>` style tokens by first appearance, timestamps dropped or replaced by a monotonic counter). Compare to the fixture's `expected`; on a diff, print a unified diff and fail. `UPDATE_FIXTURES=1 cargo test --test fixtures` rewrites `expected` in place.
- The fixtures, at least one each and a second where a branch matters: `create_action` (a signed spend with change; an unsigned `noSend`; a spend with no change; insufficient funds), `create_action_offering` (an offered set of 100, allocation and the rows written), `process_action` (sign and send; `noSend`), `internalize_action` (wallet payment; basket insertion), `abort_action`, `list_outputs` (basket, tags, limit and offset), `list_actions` (labels, limit and offset), the sync's leads (`get_utxo_leads` driven through the mock). Each fixture file: `name`, `issue`, `inputs`, `calls`, `expected`. One JSON file per fixture, none over 800 lines.
- The CI job: `fixtures` in `ci.yml` running `cargo test --test fixtures --locked`; one job added, no job renamed, no other workflow change (another lane edits the triggers).
- The proof: the replay green; then a planted behaviour change (one line in the door, say the change output's position) shows a diff and a red run, reverted; the tail of both in the report. Two runs on one tree produce byte-identical fixture files.

Bounds: no change to `src/` beyond `pub(crate)` or test-only helpers the harness needs, and none to the public API or the schema; no `Cargo.toml` edit (serde_json and tokio are present; if a crate is missing, stop and say so).
